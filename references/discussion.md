# Discussion

本节骨架为导师法（「小盐的世界」《学术训练》· Discussion 篇）。Discussion 是 Introduction 的**反向镜像**：引言从宽泛到具体（漏斗型）帮助读者「进入」论文，Discussion 从具体到宽泛（倒漏斗型）帮助读者「离开」论文，方向正好相反。

## 功能模块与写作流程（导师法）

**四模块结构**：

- **模块 1 · 回顾**：回到引言/方法论/结果，建立上下文。**从哪部分切入，取决于你的核心贡献**：核心贡献是解决了引言提出的问题，就从回顾引言中的空白开始；核心贡献是方法创新，就从重访方法论开始；结果本身是亮点，就从总结结果开始。时态建议：重访方法论或结果时，过去时、现在时、现在完成时都可用（如 `HI was used / is used / has been used`）。
- **模块 2 · 映射**：将本研究定位在学术地图中——告诉读者你的工作与现有研究是什么关系，你的发现落在已有文献的什么位置上。
- **模块 3 · 成就与启示**：
- **3.1 突出贡献/创新**：明确指出你的研究的成就和创新之处——不要害羞，如果你不说，读者可能注意不到。可用语言：`Most notably, this is the first study to our knowledge...` / `Our results provide compelling evidence for...`
- **3.2 完善启示（Implications）**：解释「这些结果意味着什么」——提出可能的机制、原因或深层含义，从具体结果推导出更广泛的推论。**与 Results 的关键区别**：Results 中的启示只是用 suggesting / indicating「初步提及」；Discussion 中的启示需要**深入发展、细化和讨论**——这是 Discussion 的核心功能之一，在 Results 里点到为止的话必须在这里展开。
- **模块 4 · 局限与未来**：
- **4.1 陈述局限**：不要把局限说成「致命缺陷」；承认局限的同时尽可能提及积极方面。范式：`However, some limitations are worth noting. Although our hypotheses were supported statistically, the sample was not reassessed once the programme was over.`（承认局限，但句群紧挨着正面结果。）
- **4.2 建议未来工作**：语气区分是硬规则——**should 是向他人/社区的建议，will 是自家计划**（见语言力学的情态表）。

**完整写作流程**（导师法给出的全序，每句话都有特定功能）：从重访前人研究 → 指出前人不足 → 介绍本文方法 → 总结结果 → 映射到文献 → 突出成就 → 推导启示 → 点明创新 → 完善应用 → 承认局限 → 建议未来。拼起来才是一篇完整的 Discussion；写作时可按此序检查自己走到了哪一步、有没有跳步。

## 语言力学要点（导师法）

**情态动词是 Discussion 的核心语法工具——一套真值度（truth value）校准系统**：你经常要解释结果的原因、提出可能的机制、推测深层含义，但往往没有确凿证据证明解释一定正确；情态动词用来表达不同程度的可能性与必要性、降低被证伪的风险。六种功能：能力、可能性、概率、虚拟确定性、建议、必要性，各有权重，按证据强度精确选择。最易错的几组（完整校准表见 language-mechanics.md）：

- **may not ≠ cannot**：may not 是「可能不」（可能性类），cannot 是「不可能」（虚拟确定性类）——强度有本质区别，不可互换。
- **must = 「没有其他解释」**：表达的是逻辑推理（没有其他解释），不是直接观察到的证据；没有排除其他解释时不许用 must。
- **did not need to ≠ need not have**：`We did not need to heat the valves`＝我们不需要加热（不说明是否真的加热了）；`We need not have heated the valves`＝我们本不需要加热（隐含：已经加热了，但白费功夫）。
- **should vs will**（未来工作）：should 是建议（给他人/社区），will 是自家计划。
- **弱化组合**：情态动词＋弱化策略组合使用是 Discussion 的常见模式——即使想表达强有力的主张，通常也用 suggest + may + appears 等组合保护自己不被轻易证伪。但组合的强度仍须与证据强度匹配（见 results.md 的因果弱化原则）。

## 结构补强（nature / ARIS，注明来源）

**nature-writing · 讨论结构卡**（`static/fragments/section/discussion.md`）：

- 默认结构：`central advance -> what the evidence means -> relation to prior work -> constraints / limitations -> future use or open questions`
- **综合而非复述**：Discussion 在已确立的 Results 主张之上做综合，不逐图重复证据。
- **先处理对手解释再推广**：在概括之前先 address rival explanations——审稿人专看这一点。
- **弱化强度必须与证据强度匹配**：不要把 "consistent with" 级别的发现升格为 "demonstrates" 的措辞。（与导师法情态校准同向。）
- **局限来自论文内部**：点名结果停止成立的具体条件或数据集，不要用通用免责句。
- 句法样本：Discussion 句子做解释——`may reflect`、`suggests that`、`could indicate`、`is likely due to`、`may facilitate`。
- 常见失败模式：把 Results 再总结一遍而不是解释；跳过对手解释；省略边界（解释到哪里停止成立）；未来工作写成营销而非诚实的开放问题；不点名许可强度的设计特征就使用 `must`、`cannot`、`demonstrates` 或因果动词；列局限却不说明每条局限改变了哪条主张、范围或解释。
- 一句话记忆：Results = 建立并推进主张的证据链；Discussion = 这些主张合在一起意味着什么、与领域什么关系、这套综合何时失效。

**nature-writing · 结论结构卡**（`static/fragments/section/conclusion.md`，会议稿的 Conclusion 常与 Discussion 相邻或合并，一并执行）：默认结构 `contribution -> decisive evidence -> implication -> boundary`；无新数据、无无支撑的承诺；中心贡献一句话重述，不要逐图总结 Results；推论的范围必须 ≤ 证据的范围；有界的未来工作指针可以，泛泛的 "more work is needed" 不行。**过claim检查**：每条主张能回溯到本文证据吗？机制词（demonstrates / proves / establishes）有相应的研究设计撑腰吗？推论范围 ≤ 证据范围吗？任何 "first" 主张在所声明的范围内真的第一吗？

**ARIS `paper-write` §5（Conclusion）清单**：贡献重述必须换述（rephrase），不许从引言复制粘贴；局限 2–4 条、材料性、具体（数据集规模、算力 regime、假设 X）——只写真实存在的，不许为凑数编造；未来工作 1–2 个具体方向；venue 要求时附伦理声明与复现声明；目标约 0.5 页。

## ML/CV 与 venue 注记

- **对手解释在 ML/CV 的落点**：增益来自新机制还是来自更多参数/数据/调参？nature 卡的「先处理对手解释」在会议稿里通常对应消融与强基线对比——Discussion 里点名最可能的替代解释，并回指 Results 中排除它的那组实验；排不掉的，收窄主张而不是换词遮掩。
- **局限的落点分工**：ML 会议稿的 Limitations 常并入 Conclusion 或独立小节（ARIS：通用 caveat 只许住在 Limitations 一处，正文其他位置删掉散落的免责句）；点名失效条件（哪个数据集、哪种分布偏移、什么算力规模下结论停止成立），与 nature「局限来自论文内部」一致。
- **「first」类主张**：`this is the first study to our knowledge...`（导师法成就句式）在 CV 领域极易被审稿人用一篇漏检文献击穿——使用前必须有可述的检索范围支撑（与 introduction.md 的全称否定纪律联动），并在 gates.md 的引用抽验中复查。
- **倒漏斗的篇幅感**：会议稿正文页数紧（计到 Conclusion 结束），Discussion/Conclusion 合计通常就是 ARIS 的 12%＋0.5 页量级；导师法的完整流程十一环节在会议稿里要压缩合并（回顾＋映射常并为一段），期刊稿才展开全序。

## 本节自检清单

- [] 切入点选对：回顾从核心贡献所在的那一节（引言 gap / 方法创新 / 结果亮点）开始，不是从头流水账
- [] 映射完成：本文与现有研究的关系（延续/修正/冲突/填补）在学术地图上定位明确
- [] 贡献明说：成就与创新有明确陈述句（this is the first study to our knowledge / provide compelling evidence for 一类），没有「等读者自己发现」
- [] 启示已深发展：Results 里初步提及的启示在此展开了机制、原因或深层含义，不是换词重复
- [] 局限表述合格：无「致命缺陷」式自贬；每条局限紧挨正面面，且点名了失效的具体条件/数据集
- [] 未来工作语气无误：给社区的建议用 should、自家计划用 will，无混用
- [] 情态逐句校准：may not / cannot 未互换；must 处确已排除其他解释；did not need to / need not have 用对；弱化组合强度与证据匹配
- [] （nature）对手解释在推广之前已处理；无把 consistent with 升格为 demonstrates 的句子
- [] （nature/ARIS）结论过claim检查通过：主张可回溯、机制词有设计撑腰、推论范围 ≤ 证据范围、first 主张有检索范围支撑
- [] 整体方向是倒漏斗：从自己的具体结果走向更宽的意义，读者被「送出」论文
