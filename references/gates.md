# 投稿前闸门清单

全文成稿后逐项过，任何一项不过不许报「可投」。大改之后回归重跑相关项。执行细节回指对应 reference。

## 闸门 1 · 引用抽验

- [ ] 每条引用逐条对原文抽验：作者、标题、年份、venue 与原文一致；优先已发表的 venue 版本而非 arXiv 预印本。
- [ ] 引用支撑它所挂的那条主张——不是「这篇存在」，而是「这篇确实说了这句」。数值与引用真实性是全生态通病，此项不许抽查变通为「看个大概」。
- [ ] BibTeX 不许凭模型记忆生成：走核验链取真实条目（DBLP 检索 → CrossRef DOI 回退 → 实在取不到标 `[VERIFY]` 并人工处理）；投稿前 `[VERIFY]` 标记零残留。
- [ ] 参考文献表只含正文实际引用的条目，无膨胀、无重复条目（同篇不同 key）。
- [ ] 引用 key 格式一致（如 `{firstauthor}{year}{keyword}`）。
- [ ] 引言 Move 1 / 漏斗第一、二步的每个领域断言都能回溯到文献检索报告；gap 陈述被综述许可（无凭空制造的 gap、无「No study has examined X」式全称否定）。

## 闸门 2 · RQ 与目的句逐字一致

- [ ] 研究问题/假设在摘要、引言、方法、讨论中**逐字对应**，不许各节换述成不同版本。
- [ ] 目的句精确回应引言的 gap：gap 讲什么（机制/人群/场景），目的句就答什么——无 niche-purpose mismatch。
- [ ] 核心术语全文一贯：Methods 定义的术语名，Results、Discussion、表格、图注不许为避重复而改名（「香蕉规则」：关键词一致性）。

## 闸门 3 · 主张-证据对齐（PAPER_PLAN）

- [ ] 引言的每条主张在 Experiments/Results 有支撑证据；每个实验都有论证职责（证明有效／证明增益来自关键机制／证明目标场景价值／排除最可能的替代解释），无职责的实验删、缩、移附录或重做。
- [ ] 对照与消融紧挨它们检验的主张；结果按论证排序、不按实验时间排序。
- [ ] 结论过 claim 检查：每条主张可回溯到本文证据；机制词（demonstrates / proves / establishes）有研究设计撑腰；推论范围 ≤ 证据范围；「first」类主张在所声明范围内真的第一且有检索范围支撑。
- [ ] 过强主张已收窄到证据支持的版本，而不是换柔和同义词蒙混；弱化程度与证据强度匹配（本法）。
- [ ] 通用 caveat 只出现在 Limitations 一处，正文其他位置的散落免责句已清除。

## 闸门 3B · 防御审计（防过度防御，2026-10-10 新增）

主张-证据匹配是双向的：闸门 3 查过强，本闸门查过弱。逐项过，并产出一张**弱化审计表**随稿交付（每条被弱化的主张一行：主张、证据等级、弱化层数、是否超预算、下调理由所指的证据缺口）。预算细则见 language-mechanics.md §3。

- [ ] 全文弱化点已逐句标出并定级：每条主张的证据等级（E1–E4，见 PAPER_PLAN）与实际弱化层数对得上，无超预算弱化。
- [ ] 事实句零弱化：测量数值、方法事实、本文直接观测的结果句中，无 may / might / could / suggest 类弱化词混入。
- [ ] 单句弱化 ≤1 个装置（E4 主张除外）；suggest＋may＋appears 式叠加已拆改。
- [ ] 贡献句未自我降级：摘要与引言的贡献陈述按证据等级写满；凡语气下调处都能点名逼它下调的证据缺口，点名不出的恢复满格版。
- [ ] 防御句式黑名单零命中：自贬开场、we only、自我贬低形容词、it should be noted that 填充弱化（清单见 language-mechanics.md §3）。
- [ ] 同一主张未在摘要/引言/讨论三处重复弱化：选证据最强的一处按级写满，其余回指、不叠加。
- [ ] Limitations 只写真实局限（证据确实够不着的地方），不写保险性免责；每条局限对应一个具体的证据缺口。

## 闸门 4 · 反向提纲

- [ ] 只读首句自检（本法）：抽出每段第一句连读——引言各段首句应连成连贯的缩小版引言；全篇首句链应连成连贯叙事。一段一观点、首句即主题句，抽查不合格的段重写。
- [ ] 主张覆盖（Reverse Outline Test）：主张-证据图中每条主张都出现在首句链里；每个实验/图表都映射到一条已陈述的主张；首句不推进故事的段落重写该段。

## 闸门 5 · 跨模型评审

- [ ] 稿件由**另一个模型家族**评审（Codex 写则 Claude 审，或反之），评审维度：引言每条主张是否有证据；清晰简洁与 AI 味；逻辑缺口；页数是否合限；Related Work 是否充分（≥1 页，会议口径）；理论稿证明梗概是否足够；图表是否被清楚描述与正确引用。
- [ ] 评审意见分级处理：CRITICAL 与 MAJOR 必改并记录改法，MINOR 记录交作者裁决。
- [ ] 写作质量五遍自查：①冗余提取（删填充与 AI 味句式）②主动语态与动词活力 ③句子架构（超 40 词的句子标记处理、主谓靠近、旧信息在前新信息在后、一段一职）④关键词一致性（闸门 2）⑤数字与引用完整性（样本量、百分比、有效数字、图表数值与正文一致——与闸门 1、3 联动）。

## 闸门 6 · Venue 模板 / 页数 / 披露

- [ ] 模板用对：venue 官方模板与样式文件（如 CVPR 用 cvpr 样式、ICLR/NeurIPS/ICML 各自样式、IEEE 用 IEEEtran）；匿名要求按 venue 执行（多数 IEEE venue 不用匿名，勿误开）。
- [ ] 页数口径核对：ML 会议正文计到 Conclusion 结束，参考文献与附录不计入；IEEE 参考文献**计入**页数上限。
- [ ] 引用命令不混用：ML 会议 natbib（`\citep{}` / `\citet{}`），IEEE 用 cite 包（`\cite{}`）。
- [ ] venue 必备节与清单齐全：伦理声明、复现声明、Limitations 的落点按 venue 要求放置。
- [ ] **AI 使用披露**：各 venue 对 AI 使用声明的位置要求不同（Methods / Acknowledgements / 专门声明节等），按目标 venue 的现行政策核对落点与措辞，不许套用其他 venue 的版本。
- [ ] 收尾清单：所有 `\ref{}` / `\label{}` 对应无未定义引用；图表编号正确；无 TODO/FIXME/XXX 残留；章节文件与主文件 `\input` 一致、无陈旧文件；摘要自包含；标题具体且信息充分；**跳读测试**——只读标题、摘要、引言与 Figure 1 及图注，能复原本文的中心主张。
